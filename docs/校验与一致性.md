## 6. 一致性验证方法

### 6.1 条目级核对（**已实测通过**）

合并器内置了对拍工具：

```python
from merger.report import compare_with_reference
same, diff, only_new, only_ref = compare_with_reference("合并产物.apk", "官方修复版.apk")
```

**实测结果（2026-10-04）**：

| 指标 | 结果 |
| --- | --- |
| 条目内容相同 | **7758** |
| 条目内容不同 | **0** |
| 仅合并产物有 | **0** |
| 仅官方修复版有 | **2**（`assets/save/appdata/*` —— **故意跳过**，见下） |
| 压缩方式 | 产物 STORED 7757 / DEFLATED 1（仅 manifest）；官方 STORED 7759 / DEFLATED 4 |
| 体积 | 产物 900.9 MB / 官方 901.3 MB |
| 耗时 | **8.5 秒** |

> **结论**：合并产物与官方修复版**逐条目字节一致**，唯一差异是那 2 个被故意跳过的文件。

**为什么跳过 `assets/save/appdata/*`**：
那是 2014 年的旧存档载荷。历史教训（M9c/M9d）：它的内容全为零，
客户端启动时读到后会**删除 `save/database/master_card`**，而 `save_version` 仍标记卡表为最新
→ 不再重新下载 → 卡面解析成不存在的 `face_0` → 卡牌页面全部崩溃。
所以合并器**不写**它们，让客户端走正常的"首次启动"路径自行重建。

### 6.2 二进制补丁自查

```
# 从原版 .so 重放补丁，应与修正后逐字节一致
python merger/src/tools/make-binary-patch.py verify \
    librooneyj.orig.so librooneyj.patched.so patch-librooneyj.json

# 或直接应用到文件（带三重校验、幂等）
python merger/src/tools/apply-binary-patch.py \
    merger/patches/librooneyj.so.patch.json <目标.so>
```

**已实测的三个场景**：

| 场景 | 结果 |
| --- | --- |
| 干净原版 `.so` | `e0c4b63b…` → `36a4826b…`（54 区间 / 426 字节）✓ |
| 重复应用 | 幂等跳过 ✓ |
| 被篡改的文件 | 拒绝且**不改动** ✓ |

### 6.3 补丁描述格式

```json
{
  "format": "kssma-binary-patch/1",
  "label": "librooneyj 4 native patches",
  "from_sha256": "e0c4b63b…",
  "to_sha256":   "36a4826b…",
  "size": 4476928,
  "region_count": 54,
  "changed_bytes": 426,
  "regions": [ { "offset": 1850280, "before": "d9a8fef7d5f8", "after": "24f2fab900bf" }, … ]
}
```

**安全保证**：
1. 应用前核对整文件 `from_sha256`
2. **逐区间**核对 `before` 字节 —— 任一不符立即中止，绝不硬打
3. 应用后核对整文件 `to_sha256`

### 7.4 已知的**既有**问题（非合并器引入）

**教程路径会让客户端主动退出**（`AndroidRuntime: VM exiting with result code 0`）。

- 触发条件：**全新账号**（存档 `tutorial.step = 100`）走教程流程
- 现象：`login` 返回教程场景后，客户端立刻 `System.exit(0)`，屏幕上先显示"无法连接服务器"
- **对照实验结论**：用**官方修复版 APK** 走同样流程，**行为完全一致**
  （同样 `login tutorial step=100 -> enter tutorial` → 同样 VM exiting）
  → **这是既有的教程实现缺陷，与合并器无关**，合并产物与官方版行为等价
- 绕开方式：存档里 `tutorial.step = -1`（标记教程已完成）即直接进主城
- 待查：登录应答里教程场景的报文形状（`next_scene=100`）是否是客户端退出的原因

### 7.3 已知的设计取舍

| 取舍 | 原因 |
| --- | --- |
| 跳过 `assets/save/appdata/*` | 2014 全零旧存档会导致客户端删除卡表（见 §6.1） |
| 输出几乎不压缩（STORED） | 与公开修复版一致；引擎按偏移直读资源，省解压 |
| 不做"逐字节可复现" | 需固定签名时间戳与 zip 元数据，对用户无额外价值（目标是内容等价） |
